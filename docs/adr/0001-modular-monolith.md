# ADR 0001 — 以模块化单体交付首轮产品

状态：接受。

## 背景

PlayMatch 是面向实习投递的单人维护项目。第一阶段需要可追踪的完整用户流程、可靠的数据边界和有意义的测试，同时避免把尚不存在的规模问题写成复杂基础设施。

## 决策

前端使用 Next.js，后端使用 FastAPI，推荐流程使用 LangGraph。后端按 API、领域逻辑、持久化与上游适配器划分模块。浏览器只访问同源 Next.js 代理；密钥与外部数据请求保留在后端。

SQLite 用于最快本地启动，PostgreSQL 用于容器部署和独立的数据库集成测试。使用统一 SQLAlchemy 模型与 Alembic 迁移。服务端会话持久化，浏览器通过 HttpOnly Cookie 认证。匿名任务使用专属 capability header，不在 URL 中携带访问令牌。

首轮推荐任务在单个 API 进程中有限并发执行，并持久化状态与事件。进程重启中断的任务必须变成明确的失败状态，不能永久停在运行中。跨实例执行、队列投递与 checkpoint 恢复应在有独立验收测试后再开启。Redis/Celery 只为明确实现的可选作业服务，不能用于宣称首轮推荐已经具备分布式可靠执行。

## 代价与后续

部署初期必须保持一个 API worker；API 进程故障会中断运行中的任务。后续迁移到持久队列时，保留公开 run/event 接口，新增唯一任务投递、幂等节点、重试与故障恢复测试。
