# 离线推荐评估

这是一套用于开发和回归检查的小型评估，验证 **当前规则工作流在人工标注的目录案例上能否找到合适入口、遵守明确约束并承认数据不足**。它不是独立盲测，也不能证明真实用户的总体满意度。

## 数据与标签

标签文件是 [`evals/rules-dev-v1.json`](../evals/rules-dev-v1.json)，共 23 条案例。开发用编码 Agent 根据 24 款启动目录及其来源，先写出可接受游戏 ID、理由和约束，再运行本文件中的评估。`acceptable_ids` 没有根据当前排序自动生成，也不是所有可能合适游戏的穷举清单。

| 类别 | 数量 | 覆盖内容 |
| --- | ---: | --- |
| 主题发现 | 12 | 中文与英文种田、太空探索、侦探剧情、自动化、卡牌、海洋、赛博朋克、平台跳跃、科幻解谜，以及排除合作主题 |
| 约束和空态 | 11 | 已核验简中界面、在线合作、无恐怖但属性未知、不支持的平台、未核验人数、本地合作、无匹配、已拥有与排除反馈、国区预算无法核验、中文非必需 |

标签文件记录了标注时的目录 SHA-256。运行结果另存实际使用目录的 SHA-256，以便辨认目录是否变化。语料规模小、主题直接且与目录词汇高度重合；中文和英文配对案例也不是彼此独立的样本。开发者已经知道这些案例，并且语料产生于实现及缺陷修复过程之中，因此明确使用 `exploratory_development` 标记。

## 执行方式

在仓库根目录安装锁定的依赖后运行：

```bash
uv sync --frozen --extra dev
uv run --frozen python scripts/evaluate_recommendations.py --check
```

脚本默认读取 `evals/rules-dev-v1.json`，写出 [`evals/rules-dev-v1-results.json`](../evals/rules-dev-v1-results.json)。可通过 `--dataset` 和 `--output` 指定路径。`--check` 在任一案例失败时返回非零退出码；不带它时仍会记录失败，便于探索。案例预期不应为了让失败消失而随意改动，应先调查行为或数据是否有误，再记录有理由的标签修订。

运行的是生产代码中的 `build_graph` 和真实启动目录，而不是复制一份推荐算法或返回预先写好的推荐结果。它显式关闭 LLM 配置，并阻断同步及异步 `httpx` 请求，同时关闭 LangSmith/LangChain tracing。语料不包含需要实际报价的 US 预算请求，脚本也会拒绝这类案例。CN 预算案例只检查预算意图和“预算尚未核验”的提示，不获取外部价格。

因此，这项评估不需要 API 密钥、网络报价、账号、邮件或付费模型。它不覆盖 LLM 分支、向量检索、接口鉴权、前端交互或真实购买可行性；这些能力不能由本结果推断。

## 指标与通过条件

- **Hit@1 / Hit@3**：在主题发现案例中，前 1 / 3 个推荐至少包含一个人工标注的可接受 ID，即记为命中。分母是 12 条主题案例。该指标不代表列表中每个游戏都合适，也不能当作 Precision@k、召回率或用户满意度。
- **约束案例通过数**：检查案例声明的属性、排除项、意图字段、空结果及必要提示。有正向候选标签的约束案例也要求前 3 个结果命中至少一个可接受 ID。
- **通用检查**：输出必须是规则模式，推荐符合公开的 Pydantic `Recommendation` 合同，不能出现重复游戏 ID。脚本错误或合同校验异常均记为该案例失败。

对于未知数据，通过条件依赖当前已核验目录，而不是游戏在现实中是否可能支持某项功能。例如，“四人合作”返回空结果表示目录没有足够的人数证据，不表示世界上没有四人合作游戏。启动目录只有已核验的在线合作分类，也不能据此断言不存在本地合作版本。

## 本次真实结果

已保存结果的执行时间为 **2026-10-20 08:56 UTC**，使用 24 款启动目录、规则模式，未调用模型或外部报价。

| 指标 | 结果 |
| --- | ---: |
| 全部案例通过 | 23 / 23 |
| 主题发现 Hit@1 | 12 / 12 |
| 主题发现 Hit@3 | 12 / 12 |
| 约束案例通过 | 11 / 11 |

这些数字只说明这套已知开发案例中的检查通过，**不能表述为“推荐准确率 100%”**。逐条实际输出、警告和失败列表保存在结果 JSON，方便复核，不用只依赖汇总数字。

本次结果还暴露了指标无法充分描述的列表尾部问题：对于“温馨的农场经营游戏，种田放松”，第一名是人工期望的《星露谷物语》，但后续结果包含《环世界》和《冰汽时代》。它们共享经营或生存主题，却不充分满足温馨种田这一组合偏好。卡牌和太空案例也有类似的主题部分匹配结果。Hit@k 可以保持全命中，同时这类尾部质量仍需要改进。

下一阶段若要报告推荐质量，应另建开发过程中不使用的留出集，由独立标注者评审完整列表，对组合偏好、同义表达、明确否定和无答案情况增加覆盖；再分别报告排序相关性、硬条件违规与无答案处理。届时还应单独评估 LLM 分支及真实报价的地区、版本、激活和时效，不能把这些未执行评估写成现有成果。

## 与其他验证的关系

- Provider fixture 测试位于 `tests/provider`，验证价格单位、错误响应、限流、地区与版本边界，不使用实时价格作固定断言。
- `scripts/probe_providers.py --live` 是独立、显式触发的只读联网诊断；其结果只代表当时观测，不是持续有效的现价或服务可用性保证，见 [数据源说明](data-sources.md)。
- 当前离线脚本可作为轻量回归门槛。是否加入 CI 由仓库的实际工作流决定；本说明不把本地执行描述成已经运行的远端 CI。
